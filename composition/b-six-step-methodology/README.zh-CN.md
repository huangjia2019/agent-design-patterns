# 六步选型法

> 组合模块 · 证据驱动的架构收敛流程
> [English README](README.md)

## 工程化定义

**六步选型法是一条有顺序、有证据、可重开的架构收敛流程。** 它从一项
限定好的决策和最小基线出发，诊断当前约束，生成少量候选，审查模式接缝，
再通过同负载对照与消融决定采用、拒绝或保留基线。

这份实现不根据业务描述自动推荐模式。模式目录负责生成候选，工作负载与
运行证据负责裁决。

## 六个步骤

1. **限定决策**：写清目标、代表性负载、输出契约、约束和排除范围。
2. **运行基线**：让最小可行实现暴露真实缺口。
3. **诊断约束**：每条诊断绑定失败指标与证据。
4. **生成候选**：每个候选声明要修哪条诊断，以及成立前提。
5. **接缝与实验**：先查工件所有权、改写规则和版本，再安排完整候选与移除变体。
6. **裁决与重开**：签发版本化回执，并写下什么变化会让旧结论失效。

## 关键接口

`SixStepSession` 强制六步按顺序发生。候选跨越多个模式时，
`SeamContract` 规定工件的生产者、消费者、所有者、冻结规则和版本字段。
`ExperimentCase` 要求完整候选跑一次，并为每个模式安排一次消融。

候选只有同时满足下面三项，才能获得采用资格：

- 最小基线没有通过全部验收门
- 完整候选通过全部验收门
- 移除任一模式后，至少一项能力重新退化

多个候选都通过时，框架返回 `NEEDS_REVIEW`，不会拿一个加权总分替架构师
决定成本与风险取舍。

## 运行

```bash
uv run python composition/b-six-step-methodology/example.py
uv run pytest composition/b-six-step-methodology -q
```

薪酬接缝实验：

```bash
uv run python composition/payroll-lab/six_step_lab.py
```

Web 工作台：

```bash
uv sync --extra ui
uv run uvicorn web_app:app \
  --app-dir composition/payroll-lab \
  --port 8041
```

打开 `http://127.0.0.1:8041/42`。

## 教学边界

这份代码验证单进程内的架构决策工件。它没有替代生产环境中的流量回放、
真实外部副作用、跨服务签名、成本归因和长期漂移监控。决策回执证明的是
“这个候选在绑定负载和验收门下获得采用资格”，不代表架构永久正确。
