2026 年 8 月 5 日，ADPS 围绕记忆模块组织了第一次专题研讨。讨论从一个基础问题开始：什么信息值得跨越一次上下文保留，什么时候才需要独立的记忆系统。由此延伸到写入准入、检索工具、版本冲突、遗忘、程序性记忆以及参数记忆。

后半部分记录这些讨论如何进入记忆模块总纲和 M1–M5 模式规范。

## 1. 记忆系统的采用条件

<p class="workshop-field-note"><strong>李庆丰用两款面向不同用户的产品说明了这项选择。</strong>开发者会主动把稳定偏好写进 rules 和项目文件，因此一款 Coding 产品没有另建自动记忆；运营人员很少维护这类文件，另一款产品才需要系统自动抽取和召回。是否建设记忆服务，首先取决于信息是否需要动态变化，以及使用者是否会显式维护。</p>

研讨中对比了两类产品选择。开发者能够把稳定偏好和项目规则写进 rules、项目文件或版本库时，这些文件已经承担了记忆职责。非技术用户通常不会持续整理偏好和经验，系统才更需要自动抽取、调用和更新。

Coding Agent 还可以直接读取本地环境中的代码语言、框架和项目规范。如果另造一份自然语言副本，反而会增加偏差和过期风险。需要单独处理的记忆工作，主要是提取、检索和定期整理。

研讨会因此形成了立项前的两个问题：

1. 这类信息是否需要动态写入、跨会话复用和自动召回？
2. 使用者是否愿意、也有能力维护显式规则？

回答完这两问，团队再决定使用文件、数据库或独立记忆服务。

## 2. 记忆需要完整生命周期

记忆需要放到长期演化和组织经验复用的背景中。一个生产系统需要同时回答七个问题：记什么、何时记、怎样组织、怎样检索、怎样更新、何时遗忘、如何跨会话或组织复用。只做向量写入和相似度搜索，还不足以构成记忆系统。

讨论还确认了三条工程边界：

- **知识库**保存可复用的领域材料；记忆保存某个主体、任务或系统如何使用材料，以及使用过程中发生的事。
- **数据本体**定义业务世界的对象、属性和关系；记忆保存 Agent 使用这些对象时形成的经验。
- **控制平面**保存当前有效的权威状态。审批结果、业务状态和不可逆动作回执由数据库、状态机或账本维护；记忆保存引用、解释和历史。

这三条边界直接进入了记忆模块总纲。

## 3. 写入侧和读取侧需要分开设计

<p class="workshop-field-note"><strong>张颖峰把问题放到了写入阶段。</strong>原始文档、日志和会话先经过“知识编译”，补出摘要、实体、事件、导航和源指针；运行时的 retrieval harness 再选择精确全文、多向量、导航或关联查询。他特别指出，纯向量搜索对需要定位和跳转的 Agent 并不友好。</p>

写入侧可以将原始文档、日志和会话转换为摘要、实体、事件、导航结构和原文指针，这一过程在研讨中被概括为“知识编译”。读取侧则需要 retrieval harness：精确全文匹配、多向量搜索、导航、关联查询和原文回溯各自覆盖不同访问路径，纯向量检索无法全部代替。

这项讨论改写了 M2 的重点。M2 现在同时规范写入管线和读取管线，并要求检索结果带上版本、时间、作用域、来源指针和 trace。“知识编译”仍作为候选模式继续积累数据结构和评测方法。

## 4. 记忆写入需要准入、版本和遗忘

<p class="workshop-field-note"><strong>张栋给出了一套已经运行的筛选办法。</strong>规则先建立周或月度命中 baseline，再结合独立评分决定保留、降级和退役；命中高只说明经常被用，不能证明内容正确。他还把近一天、七天和三十天的主题摘要分开回溯，用于控制长上下文失焦。</p>

围绕分层保留、命中评分、离线审计和内生记忆，研讨形成了一个关键修正：命中次数只表示使用频率，记忆是否正确还需要独立评分。高层记忆的在线读取与离线发布也应分开，运行期 Agent 不直接改写已发布的中长期记忆。

讨论还覆盖了遗忘、动态本体、群体记忆和快照。遗忘需要根据场景配置，时间窗口、访问频率、正确性、业务风险和作用域都会影响退役决策。群体记忆需要设置共享边界、准入门槛和传播控制，防止一条错误经验扩散到更大范围。

在存储形态上，明文、激活状态和参数记忆需要处理版本共存、时间标记以及 Agent 与记忆层的解耦。这一视角让 M1 从单一的作用域分层，扩展到作用域、功能类型和访问层级三个正交维度。

## 5. 程序性记忆的边界

<p class="workshop-field-note"><strong>周默把稳定经验固化成代码，同时给出了停止条件。</strong>业务口径有限、输入输出可枚举时，生成后的程序可以复用并获得精确结果；场景变化空间近乎无限时，维护程序和分支的成本会迅速超过收益。</p>

研讨会还讨论了把稳定经验固化为代码的 Code Act 形态。它适合口径稳定、结果需要精确复现的有界任务。首次生成的程序必须完成验收，上游 schema、业务规则或依赖版本变化后需要重新认证。开放场景的变化空间过大，程序化成本会快速上升。

M5 因此补充了首次验收、适用范围和失效重认证，并继续保持扩展模式地位。

## 7. 白皮书修订

本次研讨后，记忆模块完成了以下修订：

1. 总纲增加记忆系统的使用判断，以及知识库、数据本体、控制平面三条边界。
2. M1 增加候选池、准入、分层、版本、退役和删除证明的完整链路。
3. M2 固定为“记忆 × 链式”单格，同时规范写入管线、多路索引和检索 Harness。
4. M3 加强目标契约、权威状态引用、产物式 checkpoint 和恢复后的副作用去重。
5. M4 区分原始失败事实、候选诊断和已验证 lesson，主动召回只读取已发布内容。
6. M5 保留扩展地位，补齐首次验收、适用范围和失效重认证。

记忆准入、知识编译和版本化记忆继续作为候选机制研究，本轮不为了填满矩阵增加正式模式。

## 8. 后续问题

- 无人评审的候选记忆，如何防止临时猜测进入长期召回？
- 明文、激活状态和参数记忆之间，怎样建立可复核的迁移和回滚路径？
- 动态本体如何接收新概念，同时保持旧任务可重现？
- 群体记忆的共享范围、写入权限和错误传播如何评测？
- 记忆评测如何同时覆盖写入、检索、使用和退役？
